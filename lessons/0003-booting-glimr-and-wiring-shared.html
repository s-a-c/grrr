2. Gleam & Glimr Dependencies: Preventing Lockfile Drift

When you clone an upstream starter template like glimr-org/glimr and wire it to a local path dependency (shared = { path = "../shared" }), you will hit a classic monorepo gotcha: stale template lockfiles.

What Happens on Fresh Clone

# shared/gleam.toml (Gleam 1.19)
gleam_stdlib = ">= 1.0.0 and < 2.0.0"
# shared/manifest.toml -> gleam_stdlib 1.2.0

# glimr-org/glimr template (upstream)
gleam_stdlib = ">= 0.44.0 and < 2.0.0"
# server/manifest.toml -> locked at 0.71.0 ❌

gleam deps download strictly obeys manifest.toml (like composer install), so a locked 0.71.0 conflicts with shared's >= 1.0.0 requirement.

How to Resolve & Prevent It

# 1. Align server/gleam.toml with shared/
gleam_stdlib = ">= 1.0.0 and < 2.0.0"
shared = { path = "../shared" }

# 2. Re-solve the lockfile (≈ composer update)
gleam deps update

Gleam's PubGrub solver upgrades server/manifest.toml to gleam_stdlib 1.2.0, glimr 1.4.0, and gleeunit 1.11.0 — 100% aligned with shared/.

3 Rules for Dependency Hygiene Across shared/, server/, and client/

  • Know download vs update: Use gleam deps download for fast, deterministic installs of an existing lockfile (scripts/setup-worktree.sh); use gleam deps update whenever you import a starter template, add a path dependency, or upgrade Gleam.
  • Keep gleam_stdlib bounds aligned: Match the same major range (>= 1.0.0 and < 2.0.0) across shared/, server/, and client/ so every package resolves to the exact same stdlib version.
  • Commit synchronized manifest.toml files: Always commit updated manifest.toml lockfiles together after running ./scripts/verify-lesson.sh so future worktrees and students get deterministic green builds on first run.

3. Hands-On Lab (10 minutes)

Run all commands from the root of your lesson-0003/ worktree.

  1. Clone the Glimr starter template into server/
    Remove server/.git right away so server/ is tracked cleanly inside your lesson-0003 worktree (not a nested repo): 
    # From the lesson-0003/ worktree root
git clone --depth 1 https://github.com/glimr-org/glimr.git server
\rm -rf server/.git
cd server
/bin/cp .env.example .env
  2. Align gleam_stdlib, wire shared/, and re-solve the lockfile
    Open server/gleam.toml, update gleam_stdlib to match shared/, and add shared as a local path dependency under [dependencies]: 
    [dependencies]
gleam_stdlib = ">= 1.0.0 and < 2.0.0"
# ...keep existing glimr dependencies...
shared = { path = "../shared" }
    Then run gleam deps update (instead of download) to refresh the template's stale manifest.toml lockfile: 
    gleam deps update
  3. Create your first grrr JSON endpoint using shared/
    Create server/src/app/http/controllers/api/health_controller.gleam: 
    import gleam/json
import glimr/http/response.{type Response}
import grrr/handle
import grrr/post

/// Health & shared-domain smoke endpoint for grrr.
///
/// @get "/api/health"
///
pub fn show() -> Response {
  let assert Ok(draft) =
    post.new_draft("@grrr_bot", "Glimr + shared/ is alive on BEAM! 🐻")

  json.object([
    #("status", json.string("ok")),
    #("sample_author", json.string(handle.to_string(draft.author))),
    #("sample_body", json.string(post.to_string(draft.body))),
    #("max_body_length", json.int(post.max_body_length)),
  ])
  |> response.json(200)
}
  4. Boot Glimr and test both the Loom welcome page and /api/health 
    # Inside lesson-0003/server/
./glimr run
    In a second terminal tab, hit your new API endpoint: 
    curl -s http://localhost:4567/api/health | jq .
    Also visit http://localhost:4567 in your browser to see Glimr's default Loom welcome page!
