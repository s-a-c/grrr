1. Laravel Blade vs. Glimr Loom

Every `.loom.html` file compiles directly into a Gleam module inside src/compiled/loom/ with a typed render(...) function. If you rename a field on Grrr or forget a prop on a component, Gleam refuses to compile.

Interactive Translator: Blade vs. Loom

---
import database/main/models/grrr/gen/grrr.{type Grrr}
props(grrrs: List(Grrr))
---
<x-layouts:app>
  <slot name="meta_title">grrr Admin</slot>
  <p l-if="list.is_empty(grrrs)">No grrrs yet.</p>
  <div l-else class="space-y-3">
    <x-grrr_card l-for="item in grrrs" :grrr="item" />
  </div>
</x-layouts:app>

Loom (compile-time typed): Frontmatter declares imports and props(...). :grrr="item" passes a typed Gleam Grrr struct to <x-grrr_card /> — zero runtime array lookups.

Template syntax rules: Use {{ value }} for HTML-escaped output (safe by default) and triple-mustache {{{ value }}} only when you intentionally need raw unescaped HTML. A colon-prefixed attribute like :grrr="item" or :deleted="False" evaluates a Gleam expression, whereas an unprefixed attribute passes a static string literal.

  5. Add a Loom Live Moderation Action (l-on:click over /loom/ws)
    Let's add a two-step live Delete → Confirm action to every card with zero page reloads! First, add src/database/main/models/grrr/queries/delete_by_uuid.sql (no trailing ;!) and run ./glimr db_gen: 
    DELETE FROM grrrs WHERE uuid = $1
    Next, create src/app/actions/admin_actions.gleam: 
    import database/main/models/grrr/gen/grrr
import glimr_sqlite/sqlite

pub fn delete_grrr(uuid: String) -> Bool {
  let pool = sqlite.start("main")
  let ok = case grrr.delete_by_uuid(pool, uuid) {
    Ok(_) -> True
    Error(_) -> False
  }
  ok

In-Depth: Why Doesn't the Header Count Update Live Yet?

Notice that when you delete a Grrr, the card's action area morphs to ✓ Deleted from SQLite, but the N grrrs badge in the page header stays unchanged until you refresh. That reveals an important boundary:

  • Isolated data-l-live actors: Each <x-grrr_actions> runs its own independent BEAM actor with primitive props (uuid, deleted, confirming). On each event over /loom/ws, Loom diffs the server-rendered LiveTree and patches only the changed DOM nodes in place via morphdom. The outer admin/grrrs.loom.html page is static HTML, and Glimr 1.4's live prop serializer encodes primitives rather than custom records like List(Grrr).
  • Mitigation 1 — Lightweight DOM Observer (Admin): Watch for [data-grrr-deleted] mutations in app.ts to sync the header badge.
  • Mitigation 2 — Lustre Island / Lustre SPA (Lesson 0007+): In Lustre's Model-View-Update loop, the list and every counter read from one shared immutable Model, so deleting or posting updates both automatically.
  • Mitigation 3 — BEAM PubSub + WebSocket (Later Lessons): Broadcast GrrrCreated / GrrrDeleted events from OTP actors so every open browser tab stays in sync in real time.
