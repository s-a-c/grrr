1. Eloquent vs. Glimr's Typed SQL Pipeline

In Laravel, you write imperative PHP migration files (Schema::create(...)) and query via Eloquent's dynamic ActiveRecord magic (where a misspelled column only explodes at runtime). In Glimr, you declare your table once in grrr_schema.gleam and write real .sql queries — Glimr diffs the schema to generate migrations and compiles your SQL into typed Gleam functions.

Interactive Explorer: The 4 Generated Functions per SQL Query

// Continuation-style for HTTP controllers — pairs cleanly with Lesson 0002's `use`!
pub fn index(ctx: Context(App)) -> Response {
  use grrrs <- grrr.list_recent_or_fail(ctx.app.db)
  // On DbError: short-circuits to 404 / 503 / 500 automatically.
  ...
}

Best for controllers: Takes ctx.app.db + a continuation. On DB failure, short-circuits directly to a 404/503/500 Response so your happy path stays completely flat.

Transactions (_wc) & In-Memory SQLite Tests

The _wc ("with connection") variants take a single database connection inside a db.transaction block rather than checking out a separate pool connection per query. When testing against SQLite :memory:, set DB_POOL_SIZE=1 so every query shares the same in-memory database instead of opening independent blank ones.

2. Hands-On Lab (10 minutes)

Run all commands inside your lesson-0004/server/ directory. (Tip: if you want a custom port like 4567, edit lesson-0004/server/.env before starting ./glimr run.)

  1. Generate the grrr model scaffold 
    # From lesson-0004/server/
./glimr make_model grrr
    Inspect what Glimr created under src/database/main/models/grrr/: grrr_schema.gleam and queries/ (create.sql, find.sql, list.sql, update.sql, delete.sql).
  2. Define the grrrs table in src/database/main/models/grrr/grrr_schema.gleam 
    import glimr/db/schema

pub const table_name = "grrrs"

pub fn definition() {
  schema.table(table_name, [
    schema.id(),
    schema.string("author_handle"),
    schema.text("body"),
    schema.unix_timestamps(),
  ])
  |> schema.indexes([
    schema.index(["author_handle"]),
  ])
}
  3. Add a custom SQL query src/database/main/models/grrr/queries/list_recent.sql 
    SELECT * FROM grrrs
ORDER BY created_at DESC, id DESC
LIMIT 50;
    Because the filename starts with list_, Glimr types it as returning List(Grrr).
  4. Generate migrations, apply them to SQLite, and compile the typed repository 
    # Inside lesson-0004/server/
./glimr db_gen --migrate
    Open the newly generated src/database/main/_migrations/*_create_grrrs_table.sql and src/database/main/models/grrr/gen/grrr.gleam to see the exact SQL and Gleam functions Glimr wrote for you!
  5. Expose GET /api/grrrs in src/app/http/controllers/api/grrr_controller.gleam 
    import app/app.{type App}
import database/main/models/grrr/gen/grrr.{type Grrr}
import gleam/json
import glimr/http/context.{type Context}
import glimr/http/response.{type Response}

/// List the 50 most recent Grrrs as JSON.
///
/// @get "/api/grrrs"
///
pub fn index(ctx: Context(App)) -> Response {
  use grrrs <- grrr.list_recent_or_fail(ctx.app.db)

  json.object([
    #("grrrs", json.array(grrrs, encode_grrr)),
  ])
  |> response.json(200)
}

fn encode_grrr(item: Grrr) -> json.Json {
  json.object([
    #("id", json.int(item.id)),
    #("author_handle", json.string(item.author_handle)),
    #("body", json.string(item.body)),
    #("created_at", json.int(item.created_at)),
  ])
}
    Boot ./glimr run and verify in another terminal: 
    curl -s http://localhost:8000/api/grrrs | jq .
# Expected: { "grrrs": [] }
    *(Replace 8000 with your APP_PORT if you customized server/.env.)*
