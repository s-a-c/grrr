1. Laravel Reverb + Redis vs. a Single gleam_otp Actor

In PHP/Laravel, HTTP requests are short-lived, so real-time broadcasting requires separate infrastructure (Laravel Reverb + Redis PubSub + queue workers). On the BEAM, every WebSocket connection is a lightweight Erlang process (~2 KB), and a single TimelineHub OTP actor holds their typed Subject(String) mailboxes directly in memory inside App.

Laravel (Reverb + Redis + Echo)

// Separate Reverb daemon + Redis broker + Echo JS client
broadcast(new GrrrCreated($grrr));

// Presence channels require Redis TTL heartbeats
// and separate auth/channel boilerplate...

Three moving services (PHP-FPM, Redis, Reverb) just to fan out one JSON event to open browser tabs.

Gleam on BEAM (gleam_otp + mist.websocket)

pub type HubMsg {
  Join(client: Subject(String))
  Leave(client: Subject(String))
  BroadcastGrrr(payload: String)
}
// Lives inside App(db:, cache:, hub:) — zero extra daemons!

One typed OTP actor fans out messages to every connected Mist WebSocket process in microseconds.

Typed Subject(Msg)

Compiler-checked mailboxes: A Subject(HubMsg) only accepts Join, Leave, or BroadcastGrrr — impossible to send an untyped message.

mist.websocket Selector

Exact presence cleanup: on_init registers a Selector on the client's Subject; when a tab closes, Mist invokes on_close immediately — no Redis TTL lag.

effect.batch + effect.from

Custom browser effects: init combines fetch_grrrs() and subscribe_timeline() via effect.batch; effect.from bridges WebSocket events into Lustre Msgs.

2. Hands-On Lab (12–15 minutes)

Run server commands in lesson-0009/server/ and client commands in lesson-0009/client/.

  1. Add gleam_otp to server/ and inspect TimelineHub 
    # Inside lesson-0009/server/
gleam add gleam_otp
    Review server/src/app/realtime/timeline_hub.gleam: actor.new(State(clients: [])) handles Join, Leave, and BroadcastGrrr, and sends JSON frames to every connected Subject(String).
  2. Wire hub into App, grrr_controller.store, and /ws/timeline
    In server/src/glimr_app.gleam, we intercept ["ws", "timeline"] with mist.websocket before falling through to glimr_mist.handler: 
    case request.path_segments(req) {
  ["ws", "timeline"] ->
    mist.websocket(
      request: req,
      on_init: fn(_conn) {
        let client = process.new_subject()
        timeline_hub.join(app.hub, client)
        let selector = process.new_selector() |> process.select(client)
        #(client, Some(selector))
      },
      on_close: fn(client) { timeline_hub.leave(app.hub, client) },
      handler: fn(client, msg, conn) {
        case msg {
          mist.Custom(payload) -> {
            let _ = mist.send_text_frame(conn, payload)
            mist.continue(client)
          }
          mist.Closed | mist.Shutdown -> mist.stop()
          _ -> mist.continue(client)
        }
      },
    )
  _ -> glimr_handler(req)
}
  3. Proxy /ws in client/gleam.toml and subscribe via effect.from
    lustre/dev proxies both HTTP and WebSockets when configured as a list: 
    [tools.lustre.dev]
proxy = [
  { from = "/api", to = "http://localhost:4567/api" },
  { from = "/ws", to = "http://localhost:4567/ws" },
]
    In client/src/client.gleam, init runs effect.batch([fetch_grrrs(), subscribe_timeline()]) using our 18-line @external(javascript, "./ws_ffi.mjs", "connect_timeline") FFI bridge.
  4. Open two browser tabs and watch real-time sync! 
    # Terminal 1 (lesson-0009/server/):
./glimr run

# Terminal 2 (lesson-0009/client/):
gleam run -m lustre/dev start
    Open http://localhost:1234 in two side-by-side tabs. Watch the header badge jump from ● 1 online to ● 2 online. Post a Grrr in Tab A — it appears in Tab B instantly without refreshing! Close Tab B and watch Tab A drop immediately back to ● 1 online.

In-Depth: Deduplication by UUIDv7 & Custom Lustre Effects

  • Why prepend_unique checks g.id == item.id: When Tab A submits a Grrr, it receives the new post from both the HTTP 201 Created response (GrrrPosted) and the WebSocket broadcast (WsFrameReceived). Checking the UUIDv7 id makes both arrivals idempotent so Tab A never renders a duplicate card.
  • Why effect.from(fn(dispatch) { ... }) works: Lustre passes a dispatch callback into your custom effect; whenever ws_ffi.mjs receives a WebSocket frame or open/close event, calling dispatch(WsFrameReceived(frame)) feeds it straight into update(model, msg).
  • Single-node vs. multi-node BEAM: Here one TimelineHub actor serves one BEAM node; when scaling across multiple servers, OTP's built-in pg (process groups) distributes the exact same pattern across a BEAM cluster with zero Redis.

Lesson 0009 Win Condition

Two Lustre SPA tabs stay live-synced over /ws/timeline via your BEAM/OTP TimelineHub actor: posting in one tab updates the other immediately with zero duplicates, and opening/closing tabs updates the ● N online presence badge in real time!
