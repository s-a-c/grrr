Glossary & Laravel-to-Gleam Mental Model

The core vocabulary of Gleam, Glimr, Lustre, and the BEAM — anchored to Laravel/Livewire and Laravel/React.

1. Stack Translation Map

Laravel / JS World grrr Stack Where the Analogy Holds Where the Analogy Breaks (The Upgrade)
Laravel Glimr (on Wisp + BEAM) Batteries-included routing, controllers, middleware, migrations, sessions, auth (glimr_auth). No mutable request-global service container or magic facades; dependencies are passed explicitly as typed values, and every request runs in a lightweight BEAM process.
Blade / Livewire Loom (Glimr's template engine) Server-rendered HTML templates with components, slots, directives, and server-driven reactivity for the admin portal. Templates compile down to type-checked Gleam code — missing variables or mismatched types fail at compile time, not in production.
React / Vue Lustre (MVU / Elm Architecture) Declarative UI components, SPA client routing, and interactive islands mounted onto DOM nodes. No hooks rules, no mutable component refs, no useEffect dependency arrays. One immutable Model, explicit Msg variants, pure update, and managed Effects.
FormRequest / DTO + TS types Shared Gleam Package (shared/) Defines domain models, validation rules, and JSON contracts. Compiled to both Erlang (BEAM) and JavaScript from one source of truth — zero API type drift between backend and frontend.
Reverb / Pusher + Redis BEAM / OTP Actors (gleam_otp) Powers live timeline fan-out and online user presence. Stateful, isolated processes live natively inside the BEAM VM with supervision trees — no separate Redis broker required for single-node live state.

2. Core Gleam & FP Terms

Term Definition Primary Source
Custom Type An algebraic data type (tagged union / sum type) whose variants can each carry typed fields. Checked exhaustively by case. Gleam Tour: Custom Types
Opaque Type A pub opaque type whose name is exported, but whose constructors stay private to its defining module. External code must go through your smart constructors. Gleam Tour: Opaque Types
Smart Constructor A public function (e.g. post.new_body(raw)) that validates raw input and returns Result(ValidType, DomainError), making invalid instances impossible to forge. Gleam Tour: Opaque Types
Result(ok, err) Gleam's explicit error type (Ok(value) or Error(reason)). Gleam has no exceptions for control flow; callers must handle failure. Gleam Tour: Results
Dual Target (BEAM + JS) Pure Gleam modules compile to both Erlang bytecode (for Glimr on the server) and JavaScript ESM (for Lustre in the browser). Gleam Docs
MVU (Model-View-Update) Lustre's unidirectional architecture: Model holds state, view renders HTML from state, events emit Msg, and update computes the next #(Model, Effect). Lustre HexDocs
use Expression Gleam syntax sugar (use x <- f(arg)) that passes the remaining lines of a block as an anonymous callback fn(x) { ... } to f. Eliminates nested callback pyramids in Result pipelines and Glimr/Wisp middleware. Gleam Tour: use
result.try & result.map_error result.try chains fallible steps and short-circuits on the first Error; result.map_error wraps distinct error types into a unified union so they can be chained. gleam/result HexDocs
gleam.toml vs manifest.toml gleam.toml declares version ranges (≈ composer.json); manifest.toml locks exact versions (≈ composer.lock). Use gleam deps download to install locked versions and gleam deps update to re-solve conflicts when combining packages or starter templates. Gleam Docs: gleam.toml
